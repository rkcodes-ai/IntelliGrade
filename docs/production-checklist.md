# Production Checklist (Module 08)

Run through this before pointing real traffic at a deployment. Each item
links to the file/doc that implements or documents it.

## Before first launch

- [ ] Copy `.env.production.example` → `.env.production`, fill in every
      `REPLACE_ME_*` value with a real, unique secret (never reuse a dev
      value). Generate `SECRET_KEY` with `openssl rand -hex 32`.
- [ ] Confirm `.env.production` is **not** tracked by git
      (`git check-ignore -v .env.production` should report it as ignored).
- [ ] Replace the self-signed certificate in `nginx/certs/` with a real
      CA-issued certificate (certbot/ACME or your CA) — see
      `nginx/certs/README.md`. The self-signed cert generated by
      `scripts/generate-self-signed-cert.sh` is for local/staging smoke
      testing only, never a real public deployment.
- [ ] Set `CORS_ORIGINS` in `.env.production` to the real public frontend
      domain(s) only — never `*`.
- [ ] Set `VITE_API_BASE_URL` (defaults to `/api/v1`, a same-origin relative
      path) — only change this if the frontend and API are not served from
      the same reverse proxy.
- [ ] Review `deploy.resources.limits` (cpus/memory) in
      `docker-compose.prod.yml` against your actual host capacity —
      the shipped values are reasonable starting points, not guarantees.
- [ ] Confirm the `internal` Docker network genuinely has no route from
      outside the host (defense-in-depth only holds if the host itself is
      also firewalled correctly).

## Data & migrations

- [ ] Run `alembic upgrade head` against the target database *before*
      rolling out a new backend image — migrations must be
      backward-compatible with the previous release for zero-downtime
      rollout (see `docs/upgrade-guide.md`).
- [ ] Confirm `scripts/backup/backup-postgres.sh` and
      `scripts/backup/backup-minio.sh` both run successfully against the
      target environment at least once before go-live (see
      `docs/backup-guide.md`).
- [ ] Schedule both backup scripts via cron/systemd-timer/your
      orchestrator's scheduled-job primitive — they are not self-scheduling.

## Observability

- [ ] Bring up `docker-compose.monitoring.yml` alongside the app stack;
      confirm Grafana's "IntelliGrade — API Overview" dashboard shows real
      data within a few minutes of traffic (see `docs/monitoring-guide.md`).
- [ ] Confirm `/metrics` is reachable from Prometheus on the `internal`
      network but returns 404 at the public edge (nginx explicitly denies
      it) — verify with `curl https://<domain>/metrics` returning 404.
- [ ] Confirm `LOG_JSON=true` in `.env.production` so logs are
      machine-parseable by whatever log aggregation you point at container
      stdout.

## Security

- [ ] Run through `SECURITY_CHECKLIST.md`'s Module 08 addendum
      (OWASP Top 10 walkthrough) once against the real deployment target.
- [ ] Confirm `.github/workflows/security.yml` is green (gitleaks,
      pip-audit, npm audit, Trivy) before deploying a given commit.
- [ ] Confirm Redis requires a password in this environment
      (`docker-compose.prod.yml` sets `--requirepass ${REDIS_PASSWORD}` —
      unlike the dev compose, this is not optional).

## Performance

- [ ] `DATABASE_POOL_SIZE`/`DATABASE_MAX_OVERFLOW` are sized for expected
      concurrency — the shipped defaults (10/20) are a starting point for
      a single-instance deployment, not a scaling guarantee.
- [ ] `DATABASE_CONNECT_TIMEOUT_SECONDS`/`REDIS_CONNECT_TIMEOUT_SECONDS`
      (default 3s each) stay comfortably under the Docker healthcheck
      timeout (5s) — don't raise one without raising the other.
- [ ] If load-testing a real environment (with real Postgres/Redis/MinIO
      behind it, unlike this sandbox — see `backend/loadtests/locustfile.py`),
      extend the locustfile with real business-endpoint scenarios
      (login, ingest, evaluate) before trusting capacity numbers.

## Rollback readiness

- [ ] Confirm the previous image tag (by commit SHA, from
      `.github/workflows/deploy.yml`'s GHCR push) is still available and
      pullable before rolling forward — see `docs/rollback-guide.md`.

## Known, honestly-disclosed gaps

See `KNOWN_LIMITATIONS.md`'s Module 08 section: no Docker CLI/daemon exists
in the sandbox this module was built in, so no Dockerfile or
`docker-compose.*.yml` here has been built or `config`-validated by
actually running Docker — only manually and carefully constructed against
well-known patterns. **Building and running these for the first time in a
real Docker environment is itself the first item on this checklist**,
before anything else.
